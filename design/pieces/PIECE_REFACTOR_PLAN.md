# 新版棋子重构方案

## 目标

新版棋子采用“少量共用图片 + 动态颜色 + 动态数字”的组合式渲染，不为每个数值制作一张完整大图。这样既能保持统一的手绘质感，也能控制微信小游戏包体，并继续兼容棋盘动态尺寸、合并动画和拖尾效果。

## 推荐节点结构

```text
piece
├─ Shadow          # 共用阴影，可选
├─ Body            # 共用白色底板，通过 Sprite.color 动态染色
├─ Highlight       # 共用柔和高光，不随数字单独出图
├─ Decoration      # 高级棋子的星光、皇冠等可选装饰
├─ Value           # Label 或 BMFont，运行时显示数值
└─ TrailEmitter    # 保留当前粒子拖尾
```

层级顺序应保证拖尾在棋子后方，数字始终位于底板、高光和装饰上方。

## 素材方案

### 必需素材

| 素材 | 建议规格 | 用途 |
| --- | --- | --- |
| `piece-body.png` | 128×128 或 160×160，透明 PNG | 白色或浅灰底板，运行时染色 |
| `piece-highlight.png` | 与底板一致，透明 PNG | 很轻的手绘高光与纸张质感 |
| `piece-shadow.png` | 128×128，透明 PNG | 所有棋子共用的软阴影，可选 |

底板需要保留透明边缘，圆角、描边和纹理画进图片；主体尽量使用中性白色，避免染色后偏色。不要使用 1024×1024 的单棋子源图直接进入项目。

### 数字

优先保留动态 `Label`，并使用项目内置的自定义字体，避免微信平台使用系统字体时产生差异。如果普通字体无法达到设计稿的手绘感，再制作一套只包含 `0–9` 的 BMFont 图集；不要把数字烘焙进每种棋子图片。

### 分级装饰

- `2–64`：仅底板、数字和轻高光。
- `128–512`：可增加很轻的角标、星点或纹理。
- `1024` 及以上：允许增加皇冠、光环等独立装饰，但应复用同一套小图并由代码控制显隐。

装饰只负责等级感，不能遮挡数字或改变棋子的实际碰撞、布局尺寸。

## 颜色与数据映射

棋子数值、颜色、文字颜色和装饰等级继续集中维护在 `PieceController` 的样式表中。建议后续将样式扩展为：

```ts
type PieceStyle = {
  bodyColor: string
  textColor?: string
  decoration?: 'none' | 'sparkle' | 'crown'
}
```

`setValue()` 仍然是唯一的棋子视图更新入口。玩法逻辑只传入数值，不直接操作 Sprite、Label 或装饰节点。

## 对现有实现的改造边界

当前实现位于：

- `assets/prefab/piece.prefab`
- `assets/script/PieceController.ts`

现状是 `Graphics` 绘制圆角底板，`Label` 显示数字。重构时：

1. 保留 `piece.prefab` 根节点、`Value` 和 `TrailEmitter`，避免影响现有 Prefab 引用与动画逻辑。
2. 在 Prefab 内增加 `Shadow`、`Body`、`Highlight` 和 `Decoration` 节点。
3. 用 `Body` 上的 `Sprite` 替代运行时创建的 `Graphics` 底板，通过 `Sprite.color` 应用数值颜色。
4. `Highlight` 与 `Shadow` 使用共用 SpriteFrame；`Decoration` 根据样式表显隐或切换 SpriteFrame。
5. 保留当前按棋盘格尺寸动态缩放数字、拖尾和棋子节点的逻辑，禁止写死格子坐标。
6. `PlayController`、`BoardModel`、合并、重力和技能结算逻辑不需要因视觉重构而改变。

如果底板需要适配非正方形尺寸，优先设置为 `Sprite.Type.SLICED` 并配置九宫格；当前棋盘为正方形格子时可先使用普通 Sprite。

## 包体控制

- 单张透明棋子基础图建议控制在 10–40 KB。
- 共用层优先合入一个小图集，避免大量碎图和 Draw Call。
- 不保存每个数值的完整棋子图，也不同时保留多套历史导出图。
- 原始高清绘制稿放在设计目录，进入 `assets` 的只保留裁切、缩放和压缩后的运行时素材。
- 导入 Cocos 后再针对微信小游戏配置合适的纹理压缩，并在真机检查透明边缘。

## 验收标准

- `2` 到当前最高数值均能正确显示，三位数以上不溢出。
- 棋盘尺寸变化后，底板、数字、装饰和拖尾仍然对齐。
- 快速下落、相邻合并、连锁、重力和技能结算行为不变。
- 合并动画期间没有图层穿插、白边、黑边或颜色闪烁。
- 微信小游戏真机上字体、透明边缘和颜色与 Web 预览基本一致。
- 新版运行时棋子素材总量保持在合理的小体积范围内。
