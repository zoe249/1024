# 1024 奶油风 UI 素材

## 目标

交付能直接放入 `assets/resources/` 的轻量 PNG，在 Cocos Creator 3.8.8 中缩小后轮廓仍清晰，且不增加微信小游戏主包风险。

## 风格约束

- 下列风格、像素、透明度和体积要求适用于所有新生成或优化的 UI 位图素材，不能只在弹窗背景、按钮、皇冠和功能图标上执行。
- 使用温暖奶油白、蜂蜜金、珊瑚橙、柔和叶绿和深暖棕轮廓。建议基础色：`#FFF9ED`、`#F6B43A`、`#FF6848`、`#7DBD43`、`#62391F`。
- 哑光手绘卡通、圆润轮廓、少量两段式色块阴影。禁止白色高光线、镜面反射、镜头光晕、重噪点和写实材质。
- 白色内区必须干净：使用单一奶油色，Alpha 为 `255`；不允许渐变光圈、纸张纹理或多档半透明像素。
- 除非用户明确要求，不把文字、排名数字或动态数据烘焙到图片。前三名皇冠中心留空，界面不叠加 `1/2/3`。
- 同一弹窗的动物、植物和面板只有一个组合层级。已烘入背景的装饰不再用独立 Header 重复叠加。

## 像素与文件大小

除固定为 `256×256` 的图标外，源图不得超过运行时显示尺寸的 2 倍。优先使用下表规格；“目标”是日常交付预算，“硬上限”不得超过。

| 类型 | 源图像素 | 建议显示尺寸 | 目标体积 | 硬上限 |
| --- | --- | --- | ---: | ---: |
| 图标（含排名皇冠、微型图标和功能图标） | 必须为 `256×256` | 按界面需要缩放 | 64 KB | 100 KB |
| 榜单行底图 | `650×96` | `610×76` | 16 KB | 32 KB |
| 横向按钮 | 最大 `640×228`，优先 `560×128` | 次按钮优先 `420×96` | 48 KB | 96 KB |
| 弹窗背景 | 最大 `750×1200`，优先 `720×1040` | 宽度不超过 `720` | 160 KB | 256 KB |
| 弹窗头部装饰 | 最大 `720×384` | 宽度不超过 `720` | 96 KB | 128 KB |

每个新功能新增的 UI PNG 合计优先不超过 `512 KB`。项目微信主包上限为 `4 MB`；已有构建产物时，需再执行 `npm run postbuild:wechat` 检查，不得为了校验而伪造构建目录。

### 图标小尺寸规则

- 所有图标画布必须是方形，像素宽高必须为 `256×256`，单个文件不得超过 `100 KB`；排行榜皇冠、微型图标和功能图标均不例外。
- 同组图标的主体最大边、透明安全边距和视觉重心应统一，不能只统一画布尺寸。以缩放后并排查看时的视觉重量一致为准，避免窄长图形显得明显更小或厚重图形显得明显更大。
- 画布和内容边界对齐整数像素；通常四周保留 `6%–10%` 透明安全边距，并通过光学居中修正不对称轮廓。该比例只是生成起点，同组图标的一致性优先于固定边距比例。
- 轮廓粗细应按实际显示尺寸设计，缩小后仍保留至少 `2 px` 的视觉轮廓。
- 只保留一个主轮廓和最多两层内部色块；删除缩小后低于 `2 px` 的装饰。
- 透明背景使用真实 Alpha，边缘不得带黑底、白边或未预乘杂色。

### 有效尺寸与视觉重量

- “有效尺寸”是透明画布内可见主体的 Alpha 包围盒，不是 PNG 的 `256×256` 画布尺寸。测量时同组素材使用同一阈值，默认以 `Alpha > 4` 计入包围盒，避免极淡抗锯齿像素干扰结果。
- 必须结合运行时 `UITransform` 判断大小。运行时有效宽度按 `素材有效宽度 ÷ 素材画布宽度 × 节点显示宽度` 计算，高度同理；节点显示尺寸不同时，不能直接把源素材包围盒设成相同像素。
- 先确定同组图标期望的运行时有效宽高，再反推素材包围盒：`目标素材有效宽度 = 目标运行时有效宽度 × 素材画布宽度 ÷ 节点显示宽度`。保持纵横比，不得分别拉伸宽高。
- 数值相等不代表视觉重量相等。房屋、圆环等封闭或实心图形通常比纸飞机、耳机等细长或镂空图形显大；必须在最终运行时尺寸下并排查看，并对主体占比做小幅光学校正。
- 交付前同时记录每个图标的素材有效包围盒和运行时有效宽高。若替换后仍出现“同画布但大一圈”，优先修正素材主体占比或节点显示尺寸，不用额外透明画布掩盖问题。

## 工作流程

1. 先检查 `assets/resources/` 和使用该素材的脚本，确认能否复用现有素材、实际 `UITransform` 尺寸及同组参考图标的 Alpha 有效包围盒。
2. 新的位图素材使用 ImageGen，并在提示词中明确：用途、单个对象、透明背景、奶油配色、哑光、无高光、无文字、目标像素和小尺寸可读性。每个独立素材使用独立生成调用。
3. 生成后剪掉无效空白，根据运行时目标有效尺寸反推素材包围盒，再按上表缩放和光学居中。不直接把 1K/2K 原图放入项目。
4. 优先 PNG-8 调色板压缩，但必须复查 Alpha。如调色板把原本不透明的面板变成半透明，立即改用 RGBA PNG，并将白色内区强制为 Alpha `255`。
5. 替换已有素材时保持原文件名、相对路径和 `.meta`；非资源重映射任务不编辑、删除或重建 `.meta`。新素材放到实际加载的 `assets/resources/<Feature>/` 目录。
6. 用 `scripts/check_asset.py` 检查像素、Alpha 和硬上限；另外记录 Alpha 有效包围盒和换算后的运行时有效宽高，然后在深色底和奶油色底上都查看原尺寸及运行时缩放效果。
7. 资源更改后在 Cocos Creator 3.8.8 中触发重新导入，检查引用、普通屏、长屏安全区和按下态。无法启动 Creator 时必须明确列为待人工检查。

## 校验命令

```bash
python3 Skills/cocos-cream-ui-assets/scripts/check_asset.py --profile rank-icon assets/resources/Leaderboard/medal-gold.png
python3 Skills/cocos-cream-ui-assets/scripts/check_asset.py --profile ui-icon assets/resources/Skills/hammer.png
python3 Skills/cocos-cream-ui-assets/scripts/check_asset.py --profile button assets/resources/Leaderboard/button-invite.png
python3 Skills/cocos-cream-ui-assets/scripts/check_asset.py --profile panel assets/resources/Leaderboard/panel-background.png
```

交付时报告最终路径、画布像素、Alpha 有效包围盒、运行时有效宽高、文件体积、生成提示词摘要、校验结果和待 Creator/真机检查项。
