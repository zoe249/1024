# 方块皮肤：带数字底图接入预留

当前仅预留接口。Base 的 `piece.imagesByValue` 为空，继续使用原底图染色和 Label；没有添加图片、修改场景或 Prefab，也没有启用皮肤入口。

未来皮肤可在 `AppearanceTheme.overrides.piece.imagesByValue` 中按数值配置一张包含底图与数字的图片，例如：

```ts
const theme: AppearanceTheme = {
  themeId: 'example_skin',
  version: 1,
  overrides: {
    piece: {
      imagesByValue: {
        2: { source: 'resources', path: 'example_skin/Pieces/2/spriteFrame', kind: 'spriteFrame' },
        4: { source: 'resources', path: 'example_skin/Pieces/4/spriteFrame', kind: 'spriteFrame' }
      }
    }
  }
}
```

以上名称与路径只是说明，仓库未添加对应主题或资源。基础资源位于 `assets/resources/base/<功能>/`，未来主题目录与 `base` 同级；示例对应 `assets/resources/example_skin/Pieces/`。接口也支持已有加载器的本地 `bundle` 和 `uuid` 引用；不支持远程 URL、任意节点绑定或 Prefab。数值必须是安全整数范围内、从 2 开始的二次幂，可以配置超过 8192 的数值。

- 棋盘、下一颗预览、结算最高块在命中该数值图片时使用原色显示，隐藏对应的数字 Label；不用设置 `bodyMode: 'fullColor'`。
- 没有配置的数值沿用已有底图、染色和 Label，不限制后续合成数值。切换到另一皮肤或 Base 时恢复底图与 Label 状态。
- 图片取代主体与数字，阴影、描边、高光和皇冠仍由已有图层配置管理，制作素材时避免重复叠加这些装饰。
- 技能碎片和临时特效仍通过 `getSpriteFrame()` 获取不含数字的 `layers.body`，并沿用样式色。未来皮肤可另外配置无字底图，使碎片与新外观匹配。
- 图片随整套游戏外观预先准备并由资源租约共享，不在 `setValue`、生成棋子或布局刷新时加载。配置中声明的资源加载失败时，候选外观整体失败；不把失败图片当作未配置而隐藏错误。
- 接入真实皮肤时仍需完成主题登记及各进入对局入口的准备流程。本次没有选择、购买、存档或线上权益功能。

验证：`verify-appearance.cjs` 覆盖按值切图、白色乘色、三个展示位置的数字隐藏与恢复、未配置高值回退、A → B → Base、碎片无数字、加载次数、配置校验、失败释放、独立所有者与子组件字段清空后的重复销毁；同时覆盖 Node 与 Creator loose 展开编译。默认输出对照和原专项脚本通过，TypeScript 检查通过。
