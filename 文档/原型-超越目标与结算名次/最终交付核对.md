| 问题 | 修正 |

| 没有与最终动画同源的明确静态入口 | 切换前、轻弹、退出、进入、完成图统一从定稿原型重新截图；不用旧 ImageGen 美术图测量最终排版 |
| 500ms 交替与计分演示的 220ms 容易混淆 | 明确目标交替 140+140+220=500ms；按钮样例共 720ms；B 的淡入在接入段前 110ms 完成 |
| 文档要求稳定后停用旧槽，浏览器仅将旧槽设为透明 | 稳定时实际隐藏旧槽，接入时才显示新槽，重播恢复 A；视觉与已确认动画保持一致 |
| 「同分不算超越」与原 `value > score` 目标选择冲突 | 同分保留 A，选择下一目标使用 `value ≥ score`；接口保持严格大于基线，补查使用整数分数减一保留恰好同分的目标 |
| 首次请求参数引用尚未返回的榜单 `self.value` | 首次使用 profileBest，响应到达后再取历史分最大值 |
| 纯目标解析的伪代码混入网络请求 | 解析只读缓存；补查移到数据层的进度更新流程中，并遵守限流 |
| 局部演示易被当成整屏布局或游戏实现验收 | 标明 375×230 局部预览；生产布局需按 Content 安全区与 BoardGeometry 验证，业务规则需接入游戏后验证 |
| 旧检查清单要求接口最大位数可读，超出了本轮七位数规格 | 原型验证为 1～7 位；后续生产代码已补超宽 SHRINK，固定字框内完整显示接口允许的 10 位分数，实际渲染仍待验收 |
| 截图捕获时半像素居中导致文件宽度为 376，而标注为 375 | 对齐整数像素后重新截图，五张定稿图均为 375×230 |
